# 实时事件设计

本轮重构把强实时页面从高频轮询切换为 WebSocket 推送，优先覆盖运行状态、控制日志、同步状态和系统状态时钟。

## 通道

- 地址：`/api/v1/ws/events`
- 协议：WebSocket
- 数据格式：JSON

## 基础结构

```json
{
  "type": "runtime.snapshot.updated",
  "timestamp": "2026-04-13T10:00:00+00:00",
  "payload": {}
}
```

## 事件列表

### `runtime.snapshot.updated`

- 用途：配置页端点总览刷新
- 载荷：
  - `config_id`
  - `items`

### `runtime.node.updated`

- 用途：节点运行状态详情刷新
- 载荷：
  - `config_id`
  - `node_id`
  - `runtime`
  - `config_state`

### `control.log.created`

- 用途：控制日志新增
- 载荷：
  - `config_id`
  - `node_id`
  - `log`

### `control.log.updated`

- 用途：控制日志状态变化
- 载荷：
  - `config_id`
  - `node_id`
  - `log`

### `endpoint.status.updated`

- 用途：端点控制页直接刷新运行状态和同步状态
- 载荷：
  - `config_id`
  - `node_id`
  - `status`

### `config.list.updated`

- 用途：首页配置卡片和左侧配置列表刷新
- 载荷：
  - `configs`

### `config.overview.updated`

- 用途：配置概览页刷新配置头、节点卡片和标签数据
- 载荷：
  - `config_id`
  - `overview`
  - `tags`

### `node.workspace.updated`

- 用途：节点公共头刷新
- 载荷：
  - `config_id`
  - `node_id`
  - `workspace`

### `node.apply.updated`

- 用途：配置预览页刷新系统态、同步态和同步状态
- 载荷：
  - `config_id`
  - `node_id`
  - `sync_status`
  - `preview`
  - `applied`

### `mesh.workspace.updated`

- 用途：Mesh 网络页刷新连接工作区
- 载荷：
  - `config_id`
  - `node_id`
  - `workspace`
  - `nodes`

### `sync.status.updated`

- 用途：配置同步状态刷新
- 载荷：
  - `config_id`
  - `node_id`
  - `status`

### `system.status.updated`

- 用途：首页和系统状态页刷新
- 载荷：
  - `summary`

### `system.status.snapshot`

- 用途：系统状态页获取完整系统聚合快照
- 载荷：
  - `summary`
  - `services`
  - `timestamp`

### `system.clock.tick`

- 用途：系统状态页按服务端时间持续刷新当前时间
- 载荷：
  - `timestamp`

### `settings.mqtt.updated`

- 用途：设置页 MQTT 表单跨页面同步
- 载荷：
  - `mqtt`

### `snapshot.list.updated`

- 用途：设置页快照列表刷新
- 载荷：
  - `snapshots`

## 前端使用约定

- 前端维护单个共享 WebSocket 连接，由实时连接管理器分发给各页面监听器
- 页面进入后先请求 REST 快照，再接收 WebSocket 增量更新
- 系统状态页不再依赖手动刷新按钮，时间和聚合状态以 WebSocket 为准
- 端点控制页收到 `endpoint.status.updated`、`control.log.created`、`control.log.updated` 后直接更新页面状态，不再为这些事件追加 HTTP reload
- 首页、左侧配置列表、配置概览、节点公共头、Mesh 网络、配置预览、设置页快照列表都直接消费对应快照事件
- 若 WebSocket 断开，前端提示“实时连接已断开”，并自动重连

## 后端发布约定

- 写入控制日志后立即广播
- 节点运行状态变化后立即广播
- 配置同步状态变化后立即广播
- 连接建立后立即推送一次 `system.status.snapshot`
- 连接存活期间按秒推送 `system.clock.tick`
- 不把前端展示逻辑硬编码进事件，事件只提供业务数据
