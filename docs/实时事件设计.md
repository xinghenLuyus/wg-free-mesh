# 实时事件设计

本轮重构把强实时页面从高频轮询切换为 WebSocket 推送，优先覆盖运行状态、控制日志和同步状态。

## 通道

- 地址：`/api/v1/ws/events`
- 协议：WebSocket
- 数据格式：JSON

## 基础结构

```json
{
  "type": "runtime.snapshot.updated",
  "timestamp": "2026-04-13T10:00:00+00:00",
  "payload": {}
}
```

## 事件列表

### `runtime.snapshot.updated`

- 用途：配置页端点总览刷新
- 载荷：
  - `config_id`
  - `items`

### `runtime.node.updated`

- 用途：节点运行状态详情刷新
- 载荷：
  - `config_id`
  - `node_id`
  - `runtime`
  - `config_state`

### `control.log.created`

- 用途：控制日志新增
- 载荷：
  - `config_id`
  - `node_id`
  - `log`

### `control.log.updated`

- 用途：控制日志状态变化
- 载荷：
  - `config_id`
  - `node_id`
  - `log`

### `sync.status.updated`

- 用途：配置同步状态刷新
- 载荷：
  - `config_id`
  - `node_id`
  - `status`

### `system.status.updated`

- 用途：首页和系统状态页刷新
- 载荷：
  - `summary`

## 前端使用约定

- 进入端点控制页即建立连接
- 页面卸载时主动关闭连接
- 首屏先请求 REST 快照，再接收 WebSocket 增量更新
- 若 WebSocket 断开，前端提示“实时连接已断开”，并允许手动重连

## 后端发布约定

- 写入控制日志后立即广播
- 节点运行状态变化后立即广播
- 配置同步状态变化后立即广播
- 不把前端展示逻辑硬编码进事件，事件只提供业务数据
