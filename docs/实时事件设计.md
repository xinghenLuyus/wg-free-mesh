# 实时事件设计

本文定义后台管理端当前采用的 SSE 实时事件模型。

## 目标

- 保留当前“首屏 REST + 后续实时增量”的工作方式。
- 让实时链路更适合移动端浏览器和标准 HTTP 代理。
- 让前端只消费后端事件，不承担额外业务推导。

## 通道

- 地址：`/api/v1/events/stream`
- 协议：SSE
- 数据格式：JSON
- 鉴权：`Authorization: Bearer <access_token>`

浏览器后台统一以 `/api/v1/events/stream` 作为主实时入口。

## 基础结构

SSE 输出采用标准字段：

```text
event: system.status.updated
id: 202604170001
data: {"summary": {...}, "services": {...}}
```

字段说明：

- `event`：事件类型
- `id`：事件 ID 或递增序号
- `data`：JSON 载荷

## 连接与流量原则

- 只有页面建立 SSE 连接后，服务端才会为该连接推送事件。
- 如果没有在线订阅者，服务端不应持续生成和发送无意义的流量。
- 页面关闭、刷新、登出或浏览器断开后，服务端必须及时移除对应订阅。
- 服务端不做“没有连接也持续广播”的空推送模式。
- 后端进程进入 shutdown 时，服务端必须主动结束所有 SSE 订阅，不能因为浏览器仍然打开页面而阻塞进程退出。

也就是说：

- 前端没开网页，不会有 SSE 推流。
- 有多少在线页面，就只有多少条活跃流。

## 事件分类

事件分为两类：

### 页面级快照事件

用于直接替换页面状态，避免前端自行拼装复杂视图模型。

### 增量事件

用于控制日志、运行态等连续变化内容。

## 事件列表

### `config.list.updated`

- 用途：首页配置卡片和左侧配置列表刷新
- 载荷：
  - `configs`

### `config.overview.updated`

- 用途：配置概览页刷新配置头、节点卡片和标签数据
- 载荷：
  - `config_id`
  - `overview`
  - `tags`

### `node.workspace.updated`

- 用途：节点公共头刷新
- 载荷：
  - `config_id`
  - `node_id`
  - `workspace`

### `node.apply.updated`

- 用途：配置预览页刷新系统态、同步态和同步状态
- 载荷：
  - `config_id`
  - `node_id`
  - `sync_status`
  - `preview`
  - `applied`

### `mesh.workspace.updated`

- 用途：Mesh 网络页刷新连接工作区
- 载荷：
  - `config_id`
  - `node_id`
  - `workspace`
  - `nodes`

说明：

- 当某个节点的公网入口、监听端口或其它 Mesh 依赖字段变化时，后端不仅刷新当前节点，也会向所有受影响的 peer 节点发布新的 `mesh.workspace.updated`。
- `workspace.connections[*]` 会带上连接完整性结果，供前端直接显示断裂标签，不由前端自行判断。

### `endpoint.status.updated`

- 用途：端点控制页直接刷新运行状态和同步状态
- 载荷：
  - `config_id`
  - `node_id`
  - `status`
- 触发来源：
  - heartbeat 被动上报
  - detect 主动探测 ACK 或超时
  - info/control ACK
  - 客户端 event

### `control.log.created`

- 用途：控制日志新增
- 载荷：
  - `config_id`
  - `node_id`
  - `log`

### `control.log.updated`

- 用途：控制日志状态变化
- 载荷：
  - `config_id`
  - `node_id`
  - `log`

说明：

- `info/ack`、`control/ack` 只触发 `control.log.updated`，用于更新命令状态。
- 命令行回显来自 `event` topic，服务端写入日志后触发 `control.log.created`。

### `settings.mqtt.updated`

- 用途：设置页 MQTT 表单跨页面同步
- 载荷：
  - `mqtt`

### `snapshot.list.updated`

- 用途：设置页快照列表刷新
- 载荷：
  - `snapshots`

### `system.status.updated`

- 用途：首页和系统状态页刷新聚合状态
- 载荷：
  - `summary`
  - `services`

### `system.clock.sync`

- 用途：作为系统时间校时事件，同时兼作 SSE 活性信号
- 载荷：
  - `timestamp`

说明：

- 不再按秒推送时间事件
- 前端收到 `system.clock.sync` 后，在本地按秒推进显示
- 下次收到新的 `system.clock.sync` 再做校准

## 时间同步与活性策略

系统时间事件同时承担两种职责：

1. 给系统状态页提供服务端时间基线
2. 作为连接仍然存活的轻量信号

建议策略：

- 建立连接后立即推送一次 `system.clock.sync`
- 连接存活期间每 `10s` 到 `15s` 推送一次 `system.clock.sync`

推荐首版：

- `15s` 一次

这样做的好处：

- 比每秒推送更省流量
- 比单独维护一套 heartbeat 更简单
- 页面时间仍然能持续走秒

## 前端使用约定

- 前端维护单个共享 SSE 连接，由统一事件流管理器分发给各页面监听器。
- 页面进入后先请求 REST 快照，再接收 SSE 增量更新。
- 页面退出时仅移除监听器，不允许页面组件随意关闭全局连接。
- 系统状态页不依赖手动刷新按钮，系统时间由本地走秒，周期性用 `system.clock.sync` 校时。
- 若 SSE 断开，前端只允许通过统一重连器补连，不允许多处组件竞争性重连。

## 后端发布约定

- Router 不再手写零散的 `publish_xxx()` 组合，业务完成后应生成统一的发布计划。
- 写入控制日志后立即发布相关事件。
- 节点运行状态变化后立即发布相关事件。
- 配置同步状态变化后立即发布相关事件。
- 节点或配置修改若会影响其它节点的预览、Mesh 工作区或配置应用页，后端必须一并发布受影响节点的页面快照事件。
- Mesh 连接新建、修改、删除或启停后，除了配置概览和系统状态，还必须同步刷新 `config.list.updated`，这样首页和左侧配置列表才能实时体现拓扑状态。
- 连接建立后立即推送一次当前系统状态快照。
- 连接建立后立即推送一次 `system.clock.sync`。
- 连接存活期间按低频周期推送 `system.clock.sync`。
- 无在线订阅者时不做空推送。
- 不把前端展示文案硬编码进事件，事件只提供业务数据。
- 应用 shutdown 时由实时服务主动唤醒所有订阅队列，让 `/api/v1/events/stream` 尽快退出。
