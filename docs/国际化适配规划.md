# 国际化适配规划

## 结论

本项目国际化采用“后端轻改、前端完整翻译”的方案。

后端不承担整页翻译，也不维护完整语言包。后端只负责：

- 保存用户界面语言偏好。
- 返回稳定错误码和完整 `detail`。
- 默认错误消息逐步改为英文，作为 API 和 MCP 的技术回退。
- 不把用户界面文案写进业务 payload。

前端负责：

- 页面文案翻译。
- 表单校验翻译。
- 通知与弹窗翻译。
- 错误码翻译。
- Element Plus 语言切换。
- 日期时间本地化。
- setup 流程中的语言选择。
- 设置页中的语言修改。

## 为什么这样设计

项目架构是 FastAPI API + Vue 控制台，不是后端模板渲染网页。

用户最终看到的绝大多数内容都在 Vue 前端中，前端拥有完整页面上下文，因此前端做最终翻译最自然。

后端如果做动态翻译，会带来额外复杂度：

- `Accept-Language`、请求头、用户设置之间的优先级复杂。
- API/MCP 消费方更难获得稳定英文回退。
- 后端业务逻辑容易混入展示文案。
- SSE 和 REST 事件 payload 容易变成“语言相关数据”。

因此最终方案是：

> 后端提供稳定语义，前端根据语言偏好进行完整 i18n 展示。

## 支持语言

首版支持：

- `zh-CN`：简体中文，默认界面语言。
- `en-US`：英文。

后续扩展其它语言时，不改变后端接口结构，只新增前端语言包。

## 语言偏好来源

前端语言来源优先级：

1. 后端 `system_settings.ui_locale`
2. 前端本地缓存
3. 浏览器语言
4. 默认 `zh-CN`

系统未初始化时，setup 第一步选择语言，先写入前端本地状态。初始化密码成功后，后端把该语言写入 `system_settings.ui_locale`。

系统已初始化后，设置页语言选项负责更新后端 `ui_locale`。

## 后端最小改造范围

### 1. setup 请求携带语言

`POST /api/v1/auth/setup` 请求体增加：

```json
{
  "password": "...",
  "locale": "zh-CN"
}
```

后端完成初始化密码时同步写入：

```text
system_settings.ui_locale
```

### 2. UI 设置接口

新增或扩展设置接口：

```text
GET /api/v1/settings/ui
PUT /api/v1/settings/ui
```

返回：

```json
{
  "locale": "zh-CN"
}
```

约束：

- `locale` 只允许 `zh-CN` 和 `en-US`
- 设置页切换语言时调用 `PUT /settings/ui`

### 3. 错误返回策略

后端错误结构保持：

```json
{
  "success": false,
  "error": {
    "code": "CONFIG_NAME_EXISTS",
    "message": "Config name already exists",
    "detail": {}
  }
}
```

国际化展示规则：

- 前端优先根据 `error.code` 翻译。
- 找不到翻译时回退 `error.message`。
- 后端 `message` 逐步改成英文默认消息。

### 4. 不做的后端事项

后端首版不做：

- 后端语言包。
- 后端动态翻译。
- `Accept-Language` 动态返回中文/英文。
- SSE 文案翻译。

## 前端架构

推荐引入：

```text
vue-i18n
```

新增目录：

```text
front/src/i18n/
  index.ts
  locale.ts
  messages/
    zh-CN.ts
    en-US.ts
```

新增偏好状态：

```text
front/src/stores/preferences.ts
```

职责：

- 保存当前语言。
- 初始化语言。
- 切换语言。
- 同步 Element Plus locale。
- 同步后端 `settings/ui`。

## 前端语言包分组

语言包按业务域组织：

```text
common
auth
layout
system
settings
config
node
mesh
apply
endpoint
download
errors
validation
```

示例：

```ts
{
  common: {
    save: '保存',
    cancel: '取消'
  },
  errors: {
    AUTH_REQUIRED: '请先登录'
  }
}
```

## setup 页面改造

setup 改为两步：

1. 选择语言
2. 初始化管理员密码

行为：

- 第一步选择语言后，页面立即切换当前语言。
- 第二步初始化密码时，把 `locale` 一起提交到后端。
- setup 成功后，前端保存 token，并保留已选语言。

## 设置页语言选项

设置页新增“语言”设置：

- 简体中文
- English

行为：

- 切换后立即生效。
- 写入前端本地缓存。
- 调用 `PUT /api/v1/settings/ui` 持久化。
- Element Plus 语言、日期格式、页面文案同步切换。

## 错误翻译策略

前端错误展示统一走：

1. 如果存在 `errors.<code>` 翻译，显示翻译。
2. 否则显示后端 `message`。
3. 否则显示通用 fallback。

这样后端只要保证错误码稳定，前端就能做到完整本地化。

## 表单校验策略

表单校验不再写死：

```text
名称不能为空
```

而是通过 `validation.required` 加字段名翻译生成：

```text
{field} 不能为空
```

英文：

```text
{field} is required
```

## 日期时间策略

`dateTime.ts` 改为根据当前 locale 创建 formatter：

- `zh-CN`：中文日期格式
- `en-US`：英文日期格式

## Element Plus

根组件使用 Element Plus `ConfigProvider` 包裹：

- `zh-CN` 对应 Element Plus `zh-cn`
- `en-US` 对应 Element Plus `en`

## 落地状态

当前已落地：

- `vue-i18n` 基础设施、`zh-CN` 与 `en-US` 语言包。
- `preferences` store，负责语言读取、切换、本地缓存和后端持久化。
- Element Plus `ConfigProvider` 语言同步。
- setup 两步流程：先选择语言，再设置管理员密码。
- 设置页语言切换。
- 全局通知、表单校验、日期时间、API 错误码翻译。
- 首页、布局、帮助、系统状态、设置、配置概览、节点工作台、Mesh、配置预览、端点控制、下载配置等主要页面文案迁移。
- 后端 `settings/ui` 接口和 setup 语言写入。
- 后端统一校验错误默认英文回退。

## 实施步骤

### 阶段 1：基础设施

1. 安装 `vue-i18n`
2. 建立 i18n 目录和语言包
3. 建立 preferences store
4. 接入 Element Plus ConfigProvider
5. 改造 dateTime

### 阶段 2：后端轻改

1. `SetupRequest` 增加 `locale`
2. setup 写入 `system_settings.ui_locale`
3. 新增 `settings/ui` 读写接口
4. 前端 API 类型同步

### 阶段 3：setup 和设置页

1. setup 两步化
2. 设置页新增语言选项
3. 语言切换立即生效

### 阶段 4：全局和页面文案迁移

1. 布局和导航
2. 登录页
3. 系统页
4. 下载配置页
5. 配置与节点页面
6. Mesh、配置预览、端点控制
7. 设置页与备份恢复

### 阶段 5：错误与校验

1. client 错误展示优先翻译 code
2. formRules 接入 i18n
3. 通知和弹窗文案迁移

### 阶段 6：清理与验证

1. 搜索直接硬编码中文 UI 文案
2. 搜索未翻译错误码
3. `pnpm typecheck`
4. `python -m mypy app`
5. 手动检查 setup、登录、设置页、下载页

## 协作约定

国际化落地后：

- 新增前端用户可见文案必须走 i18n。
- 新增后端错误码必须补前端 `errors` 翻译。
- 后端默认错误消息使用英文。
- 后端不得为网页展示拼接多语言句子。
- 前端不得直接依赖后端中文 message 作为最终展示文本。
