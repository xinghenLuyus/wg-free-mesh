# 重构差距清单

本文用于对比“旧系统真实能力”与“当前新重构状态”，帮助后续重构按优先级恢复系统主线功能。

## 结论摘要

当前新重构版本已经完成：

- 新目录结构
- FastAPI 后端骨架
- Vue 3 + Element Plus 前端骨架
- pnpm 构建链路
- SQLite 基础持久化

但它仍然只是“可运行骨架”，还不是旧系统的等价重构版本。

## 差距分级

- `阻断`
  - 不补齐就无法称为旧系统重构版
- `重大`
  - 会直接导致核心业务链路缺失
- `一般`
  - 不影响主闭环，但会影响完整性和可维护性

## 差距清单

### 1. 认证初始化闭环

旧系统：

- 首次初始化
- 登录失败计数
- 锁定策略
- Cookie 会话
- 中间件保护

当前新系统：

- 只有演示型登录 / session / logout

差距级别：

- `重大`

### 2. 配置模型字段严重不足

旧系统配置字段：

- `virtual_subnet`
- `default_listen_port`
- `default_mtu`
- `default_dns`
- `auto_sync`

当前新系统：

- 仅保留名称、描述、启用状态、节点计数

差距级别：

- `阻断`

### 3. 节点模型字段严重不足

旧系统节点字段：

- `ipv4_address`
- `ipv6_address`
- `listen_port`
- `virtual_ip`
- `mtu`
- `dns`
- `public_key`
- `private_key`
- `auto_sync`
- `node_type`

当前新系统：

- 仅保留名称、角色、地址、状态

差距级别：

- `阻断`

### 4. 缺失 `static/dynamic` 节点边界

旧系统：

- `static` 只生成配置
- `dynamic` 进入 MQTT 控制闭环

当前新系统：

- 没有这个核心区分

差距级别：

- `阻断`

### 5. Mesh 链路建模缺失

旧系统：

- 双向链路
- `allowed_ips`
- endpoint 来源规则
- keepalive
- psk

当前新系统：

- 只有 links 列表和非常基础的 validate

差距级别：

- `阻断`

### 6. WireGuard 配置生成缺失

旧系统：

- 生成每节点 `.conf`
- 预览
- 写入 `data/wireguard/...`

当前新系统：

- 没有真实配置生成，只是占位

差距级别：

- `阻断`

### 7. 配置状态机缺失

旧系统：

- `desired`
- `staged`
- `confirmed`
- `reported_local`

当前新系统：

- 没有配置状态真相模型

差距级别：

- `阻断`

### 8. MQTT 控制闭环缺失

旧系统：

- config push
- control
- ack
- status
- offline

当前新系统：

- 只有端点控制占位接口，没有控制面实现

差距级别：

- `阻断`

### 9. enrollment / `.wgm` / client bootstrap 缺失

旧系统：

- 下载 `.wgm`
- enrollment token
- `/api/client/enroll`
- 返回 identity 与 MQTT bootstrap

当前新系统：

- 完全未实现

差距级别：

- `阻断`

### 10. Go 客户端整体缺失

旧系统：

- Agent
- MQTT worker
- WireGuard 本地管理
- IPC / Tray / Windows Service

当前新系统：

- `client/` 为空

差距级别：

- `阻断`

### 11. 端点控制页只有外壳

旧系统：

- 运行态
- 探测
- 控制
- 日志
- 同步状态
- 客户端下载

当前新系统：

- 只有节点列表和简单按钮

差距级别：

- `重大`

### 12. 设置页能力不足

旧系统：

- 客户端 MQTT 参数维护
- 连接测试
- 受签名保护的客户端 MQTT bootstrap

当前新系统：

- 仅回显极简系统配置

差距级别：

- `重大`

### 13. 备份恢复能力不足

旧系统：

- 创建 / 列表 / 下载 / 上传 / 恢复 / 删除 / 备注

当前新系统：

- 只有创建备份占位接口

差距级别：

- `重大`

### 14. 系统状态能力不足

旧系统：

- 系统状态聚合
- healthcheck

当前新系统：

- 只有健康检查

差距级别：

- `一般`

### 15. 生产部署形态未对齐

旧系统：

- FastAPI 直接挂前端模板和静态资源

当前新系统：

- Docker 仍是前端单独镜像方案

目标调整：

- 本地开发继续前后端双开
- 生产构建产出 `dist`
- Docker 镜像复制 `dist` 到后端
- FastAPI 统一托管前端产物与 API

差距级别：

- `重大`

## 建议恢复顺序

### 阶段 A：恢复后端核心模型

优先恢复：

- `wireguard_configs`
- `nodes`
- `node_peer_links`
- `node_config_state`
- `endpoint_runtime_status`
- `endpoint_control_logs`
- `client_enrollment_tokens`

### 阶段 B：恢复配置生成与状态机

优先恢复：

- WireGuard 配置生成
- `desired/staged/confirmed/reported`
- 服务端应用配置写盘

### 阶段 C：恢复端点控制闭环

优先恢复：

- MQTT topic 设计
- config push
- control / ack
- status / offline
- endpoint runtime view

### 阶段 D：恢复 enrollment 与客户端协作

优先恢复：

- `.wgm`
- enrollment API
- MQTT bootstrap
- 客户端目录规划

### 阶段 E：恢复页面级业务能力

优先恢复：

- 配置详情页
- Mesh 页面
- 配置应用页
- 端点控制页
- 设置页
- 备份恢复页

## 当前重构原则修正

后续重构不再以“先做漂亮管理台”为主，而改为：

1. 先恢复旧系统业务边界
2. 再用新前端技术栈重建页面体验
3. 前端只重写表现层，不削弱后端与客户端闭环
4. Docker 生产形态调整为 FastAPI 托管构建产物
