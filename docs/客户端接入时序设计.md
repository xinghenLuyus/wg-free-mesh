# 客户端接入时序设计

## 目标

本文件只描述动态节点客户端接入、绑定、上线、异常掉线和重置客户端的时序。

它和 [客户端设计](D:/wenjian/stepsave/project/wg-free-mesh/docs/客户端设计.md) 与 [MQTT消息协议设计](D:/wenjian/stepsave/project/wg-free-mesh/docs/MQTT消息协议设计.md) 配套使用。

## 页面入口时序

动态节点进入端点控制页时，默认不直接显示真正控制页，而是先进入客户端初始化页。

初始化页包含：

1. 第一步：下载客户端
2. 第二步：生成节点绑定命令并复制

当后端返回 `client_initialized=true` 后，页面切换到真正控制页。

静态节点不显示绑定命令能力。

## 一次性绑定命令生成

```mermaid
sequenceDiagram
    participant U as "管理员"
    participant F as "前端控制台"
    participant B as "wfm 后端"

    U->>F: 点击“生成节点绑定命令并复制”
    F->>B: POST /api/v1/configs/{config_id}/nodes/{node_id}/bind-command
    B->>B: 校验节点为 dynamic
    B->>B: 生成 5 分钟一次性 bind token
    B-->>F: 返回 command + expires_at
    F-->>U: 复制命令到剪贴板
```

约束：

- token 默认有效期 5 分钟
- token 只能成功使用一次
- 节点转静态或执行重置客户端后，旧 token 必须失效

## bind 成功时序

```mermaid
sequenceDiagram
    participant A as "管理员终端"
    participant C as "wfmctl"
    participant B as "wfm 后端"
    participant E as "EMQX"
    participant G as "wfm-agent"

    A->>C: 执行 wfmctl bind --server --token
    C->>B: POST /api/client/v1/bind
    B->>B: 校验 bind token
    B->>B: 校验节点为 dynamic 且 token 未使用
    B->>B: 生成或轮换节点专属 MQTT 凭据
    B->>E: 创建/更新节点 MQTT 账号
    B->>B: 标记 client_initialized=true
    B-->>C: 返回 profile + mqtt + topics
    C->>G: 写入 profile 并启动 profile worker
    G->>E: 使用节点凭据建立 MQTT 连接
    G->>E: 开始周期发送 heartbeat
    E->>B: 上行 heartbeat
    B->>B: 更新客户端运行态
```

## 客户端上线后控制台页面切换

```mermaid
sequenceDiagram
    participant G as "wfm-agent"
    participant E as "EMQX"
    participant B as "wfm 后端"
    participant S as "SSE"
    participant F as "前端控制台"

    G->>E: 发布 heartbeat
    E->>B: 转发 heartbeat
    B->>B: 写入 client_initialized=true
    B->>B: 暂记客户端已接入
    B->>S: 推送 endpoint.status.updated
    S->>F: 页面收到更新
    F->>F: 从初始化页切换到真正控制页
```

## 异常掉线时序

```mermaid
sequenceDiagram
    participant G as "wfm-agent"
    participant E as "EMQX"
    participant B as "wfm 后端"
    participant S as "SSE"
    participant F as "前端控制台"

    G--xE: 异常断开
    B->>B: heartbeat 超时或 detect 失败
    B->>B: 标记 client_presence_state=掉线
    B->>S: 推送 endpoint.status.updated
    S->>F: 页面收到更新
    F->>F: 保持控制页，但状态显示为“掉线”
```

规则：

- 异常掉线不自动回到初始化页
- 因为该节点仍然是已初始化节点，只是当前连接异常

## 主动重置客户端时序

```mermaid
sequenceDiagram
    participant U as "管理员"
    participant F as "前端控制台"
    participant B as "wfm 后端"
    participant E as "EMQX"
    participant S as "SSE"

    U->>F: 点击“重置客户端”
    F->>B: POST /api/v1/configs/{config_id}/nodes/{node_id}/reset-client
    B->>E: 删除或禁用节点 MQTT 账号
    B->>B: 清空客户端运行态
    B->>B: 标记 client_initialized=false
    B->>B: 标记 client_presence_state=离线
    B->>S: 推送 endpoint.status.updated
    S->>F: 页面收到更新
    F->>F: 回到客户端初始化页
```

## 动态节点改静态节点时序

```mermaid
sequenceDiagram
    participant U as "管理员"
    participant F as "前端控制台"
    participant B as "wfm 后端"
    participant E as "EMQX"
    participant S as "SSE"

    U->>F: 保存节点类型为 static
    F->>B: PUT /api/v1/nodes/{node_id}
    B->>E: 删除或禁用节点 MQTT 账号
    B->>B: 清空绑定权限和运行态
    B->>B: 标记 client_initialized=false
    B->>B: 标记 client_presence_state=离线
    B->>S: 推送 endpoint.status.updated
    S->>F: 页面收到更新
    F->>F: 端点页恢复静态节点视图，不显示绑定命令
```

## 控制台最终页面规则

### 动态节点

- `client_initialized=false`
  - 显示客户端初始化页
- `client_initialized=true`
  - 显示真正控制页

说明：

- `client_initialized=true` 只表示该节点已完成客户端接入，不等于当前状态一定是“在线”。
- 真正在线仍由 `heartbeat + detect` 共同决定。

### 静态节点

- 永远不显示绑定命令
- 端点控制能力保持禁用或只读占位

## 最终状态语义

控制台对客户端只保留三态：

- `在线`
- `掉线`
- `离线`

投影规则：

- 首次未绑定：`离线`
- 收到遗言：`离线`
- 重置客户端、节点转静态、权限回收：`离线`
- heartbeat 超时：`掉线`
- detect 失败或 detect 返回综合异常：`掉线`
- heartbeat 正常且 detect 成功：`在线`
