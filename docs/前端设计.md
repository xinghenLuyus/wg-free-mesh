# 前端设计

## 目标

前端使用 `Vue 3 + Vite + TypeScript + Element Plus`。页面信息架构按“配置 -> 节点 -> 节点能力模板”组织。

配置是业务入口，节点是能力承载单元。Mesh 网络、配置预览、端点控制都归属到具体节点页面中。

## 视觉约定

- 采用偏精致工具型控制台的视觉方向，强调清晰层级、轻量阴影、稳定交互反馈
- 全局按钮、输入框、表格、弹窗使用统一圆角、聚焦态、悬停态和主色体系
- 结构性图标统一使用 Element Plus Icons，不使用表情符号作为功能图标
- 弹窗需要包含简短说明区，明确本次操作会影响的业务对象
- 表单字段必须保留可见标签，复杂开关使用说明行，不只依赖占位符
- 首页配置卡片、配置概览节点网格、节点列表长条卡片保持同一套卡片语言
- 设置页按登录密码、MQTT 配置、备份与恢复分组展示，备份不使用传统表格，使用长条卡片
- 交互元素需要可键盘聚焦，焦点状态不能被移除
- 全局通知和业务反馈统一使用右上角弹窗，不在页面主体中临时堆叠系统提示
- 右上角通知的关闭按钮外框展示环形进度，进度结束后自动关闭，鼠标悬停通知时暂停进度和关闭计时
- 系统状态入口点击后进入系统状态页
- 页面跳转使用统一的快速弹入/弹出动效，优先使用 `transform` 和 `opacity`，避免影响布局稳定性
- 登录/主应用、主内容区域、节点模板切换分层使用动效，避免整个应用壳在内部页面跳转时反复重载
- 用户系统开启减少动态效果时，前端必须关闭位移、缩放和模糊类动效
- 需要持续刷新的服务端数据优先通过共享 WebSocket 接收，不依赖手动刷新按钮

## 核心原则

- 首次进入系统时，前端先读取后端认证状态；未初始化跳转 `/setup`，未登录跳转 `/login`
- 登录成功后保存服务端下发的 Bearer Token，后续所有后端请求由全局拦截器统一附带
- 左侧配置列表只显示配置，不展开配置子页面
- 点击配置默认进入配置概览页
- 配置概览页保留配置头，并在配置属性下方管理节点
- 点击节点卡片进入节点页面
- 节点页面上方展示公共节点头，下方切换三个能力模板
- “同步配置”默认表示系统态同步到同步态
- 同步态到下发态必须明确写成“下发”
- 下发态属于客户端流程，配置预览页不展示下发态

## 左侧导航

左侧主导航包含：

- 首页
- 设置
- 帮助
- 配置列表

左侧导航整体使用一体化的圆角竖向气泡轮廓，不做贴边硬分栏；桌面端与页面边缘留出呼吸空间，系统状态入口作为同一气泡体系的底部卡片。
- 退出登录
- 系统状态入口

## 认证与初始化

前端认证由 `Pinia auth store` 统一管理：

- `setup_required` 表示需要设置初始管理员密码。
- `authenticated` 表示当前 token 通过服务端校验。
- `access_token` 保存到 `localStorage`，刷新页面后通过 `/api/v1/auth/state` 恢复状态。

路由守卫规则：

- `setup_required=true` 时只允许访问 `/setup`。
- 已初始化但未登录时，业务页面跳转 `/login?redirect=...`。
- 已登录访问 `/login` 或 `/setup` 时跳转首页或原 redirect。

请求拦截规则：

- 除登录和初始化外，axios 请求统一附带 `Authorization: Bearer <token>`。
- 业务接口返回 `401` 时清理 token 并跳转登录页。
- 返回 `AUTH_SETUP_REQUIRED` 时清理 token 并跳转初始化页。

WebSocket 不经过 axios，连接地址需要携带 `token` 查询参数。前端维护共享连接，页面通过监听器消费实时事件，不为每个页面单独创建长期连接。

配置列表只显示配置名称。配置下不再展开：

- 概览
- Mesh 网络
- 配置预览
- 端点控制

## 配置概览页

路由：

```text
/configs/:configId
```

页面结构：

- 配置头
  - 配置名称
  - 启用状态
  - 设置入口
  - 描述
  - 虚拟网段
  - 节点数
  - 首页配置卡片不显示动态节点数量，虚拟网段和节点数左右平分展示
  - 默认 DNS
- 节点工作区
  - 标签管理
  - 新建端点
  - 排序方式
  - 按标签筛选
  - 网格 / 列表视图切换

默认使用网格视图展示节点，视觉和首页配置卡片保持同类体验。

列表视图不使用传统表格，不展示表头，而是使用横向长条卡片。该视图名称仍然叫“列表”，只是视觉形态是更现代的长条卡片。

节点卡片视图模型来自后端 `overview.node_cards`。前端可以保留当前页面内的标签筛选、排序方式和网格/列表切换，但不自行拼接节点运行快照、Peer 数等业务聚合字段。

配置设置弹窗包含配置编辑和删除配置。配置设置、新建端点、标签管理等弹窗都使用统一弹窗样式：顶部标题、说明区、分组表单、底部确认按钮。删除配置属于危险区，必须和保存操作视觉分离。

节点卡片展示：

- 节点名称
- 节点类型
- 虚拟 IP
- 公网 IPv4
- 公网 IPv6
- 在线状态
- Peer 数
- 标签

节点卡片不展示：

- 监听端口
- 同步状态
- 快捷入口按钮

点击节点卡片进入节点页面。

## 节点页面

路由：

```text
/configs/:configId/nodes/:nodeId
/configs/:configId/nodes/:nodeId/mesh
/configs/:configId/nodes/:nodeId/apply
/configs/:configId/nodes/:nodeId/control
```

节点页面结构：

- 左上角返回按钮，返回当前配置概览页
- 公共节点头
  - 节点名称
  - 节点类型
  - 在线状态
  - 标签
  - 虚拟 IP
  - 公网 IPv4
  - 公网 IPv6
  - Peer 数
  - WireGuard 运行状态
- 三个模板入口
  - Mesh 网络
  - 配置预览
  - 端点控制

## Mesh 网络模板

归属到当前节点页面内，只管理当前节点的连接关系。

页面包含：

- 当前节点连接列表
- 新建连接
- 拓扑校验提示

不再显示左侧节点列表。

Mesh 网络页面不展示 WireGuard 配置文本，配置文本统一归属到配置预览页面。

当前节点连接列表使用连接卡片，不使用简单表格。连接卡片展示：

- 对端节点名称、启用状态。
- PSK 是否配置。
- 当前节点到对端节点的 AllowedIPs、Endpoint、Keepalive、地址族。

连接卡片需要保持紧凑，避免 Peer 数量变多后占用过多纵向空间。反向参数不在卡片中展开，只在修改参数弹窗中维护。

连接卡片不展示对端虚拟 IP、公网 IPv4、公网 IPv6、备注、节点类型等补充信息。PSK 状态、小型启停开关和“修改参数”按钮都收在参数卡片内部。

每张连接卡片提供小型启停开关和“修改参数”按钮。启停开关用于快速开启或关闭该组 peer，修改参数会打开双向连接参数弹窗。编辑对象是 `link_group_id`，对端节点只读，避免修改参数时改变连接对象。

停用状态的 peer 卡片使用灰态文字和弱化背景，方便快速区分。

新建连接弹窗按一条双向连接关系组织：

- 连接对象：当前节点、目标节点、连接地址族。
- 主向配置：当前节点到目标节点，AllowedIPs 默认使用目标节点虚拟 IP。
- 反向配置：目标节点到当前节点，AllowedIPs 默认使用当前节点虚拟 IP。
- 安全与备注：共享密钥 PSK 和备注。

新建连接弹窗的数据草稿必须来自后端 `peer-link-draft` 接口。前端只负责选择对端节点、选择地址族、展示草稿、允许用户调整表单并提交。AllowedIPs 默认值、Endpoint 自动摘要和缺失项警告不得在前端自行推导。

新建连接和修改连接参数弹窗都提供“PSK 自动生成”按钮。PSK 由后端接口生成，前端只写入表单。

Endpoint 模式只展示中文：

- `auto` 显示为“自动”，含义是有对向对应公网入口就写 Endpoint，没有就留空。
- `none` 显示为“不写 Endpoint”。
- `manual` 显示为“手动”，表单中标注不推荐常规使用。

连接地址族只展示 IPv4 和 IPv6。域名不是地址族；公网 IPv4 和公网 IPv6 两个字段都可以填写 IP 或域名。

## 配置预览模板

归属到当前节点页面内，只展示当前节点：

- 系统态
- 同步态

页面包含：

- 系统态预览
- 同步态编辑
- 保存同步态
- 同步配置
- 自动同步开关
- 不展示系统态版本、同步态版本
- 系统态和同步态使用卡片式代码预览区，不使用默认裸文本框样式

说明：

- “同步配置”默认表示系统态同步到同步态
- 下发态属于客户端流程，此页面不展示

## 端点控制模板

归属到当前节点页面内，只展示当前节点：

- 运行状态
- 远程控制
- 控制日志

远程控制中的“下发配置”表示同步态到客户端下发态。

端点控制页首屏先请求 REST，随后通过 WebSocket 接收 `endpoint.status.updated`、`control.log.created`、`control.log.updated` 直接更新页面，不再因为这些事件再发起 HTTP reload。

## 系统状态页

- 首屏先请求 `health` 和 `system/status`
- 后续通过 WebSocket 接收 `system.clock.tick` 更新服务端时间
- 通过 `system.status.snapshot` 和 `system.status.updated` 更新聚合状态
- 页面不保留手动刷新按钮
- 原聚合状态中的 `WireGuard` 展示位改为 `WebSocket 连接状态`，右侧直接显示 `已连接` 或 `已断开`
- WebSocket 连接状态由前端实时层自行探测，不依赖后端聚合字段直出
- 系统状态页额外展示最近心跳时间、重连次数和连接备注，用于排查移动端连接不稳定问题
- 前端实时层对移动端使用宽松心跳超时和可见性恢复宽限，不因为短暂切后台、前台唤醒或网络抖动就立刻主动切断 WebSocket
- 首页配置卡片、左侧配置列表、配置概览、节点公共头、Mesh 网络、配置预览、端点控制、设置页快照列表通过共享 WebSocket 接收实时更新

## 标签管理

初步实现范围：

- 节点卡片展示标签
- 配置概览页支持按标签筛选
- 新建端点时可填写标签
- 编辑节点时可维护标签
- 标签管理弹窗展示标签使用数量
- 标签管理弹窗支持搜索标签和快速应用筛选
- 标签管理弹窗支持创建标签
- 标签管理弹窗支持选择端点批量添加标签
- 标签管理弹窗支持从端点移除标签
- 删除标签表示从当前配置下所有端点移除该标签

暂不做全局标签重命名。删除标签仅表示从当前配置下所有端点移除该标签。

标签属于配置级资源，使用数量来自端点 `tags` 字段统计。创建、删除、批量应用和端点标签替换都通过后端标签接口完成，前端不遍历端点拼装批量业务。

## 端点设置

端点页面右上角提供“端点设置”入口。

端点设置弹窗包含：

- 名称
- 类型
- 公网 IPv4
- 公网 IPv6
- 监听端口
- 虚拟 IP
- MTU
- DNS
- 所属标签
- 自动同步
- 私钥
- 公钥
- 删除端点入口

端点设置保存后更新端点系统态数据。所属标签支持选择现有标签，也支持直接输入新标签。


公网地址必须保持公网 IPv4 与公网 IPv6 两个字段，不合并为单个“公网端点”。两个字段都可以填写 IP 或域名。Mesh 连接的自动 Endpoint 按 `endpoint_ref_family` 选择 `ipv4` 或 `ipv6`，对应入口不存在时自动留空。

节点类型在前端必须展示中文：

- `dynamic` 显示为“动态节点”
- `static` 显示为“静态节点”

## 排序方式

配置概览页节点排序支持：

- 名称
- 虚拟 IP
- 创建时间
- 在线状态
- 节点类型

不使用同步状态排序。

## 路由兼容

- `/configs` 重定向到 `/`
- `/configs/:configId/mesh` 重定向到 `/configs/:configId`
- `/configs/:configId/apply` 重定向到 `/configs/:configId`
- `/configs/:configId/endpoints` 重定向到 `/configs/:configId`
- `/backups` 重定向到 `/settings`

旧配置级能力入口保留兼容跳转，但不再作为业务页面。
