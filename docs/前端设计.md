# 前端设计

## 目标

前端使用 `Vue 3 + Vite + TypeScript + Element Plus`，但页面信息架构、主操作路径、配置内跳转关系要尽量向 `bak` 中已经验证过的布局收束。

视觉风格可以继续现代化，但不能改动旧版已经打磨好的页面组织方式。

## 核心原则

- 样式可以重做
- 页面结构和点击流向尽量向 `bak` 对齐
- 配置详情页是配置视角下的主工作台
- 节点管理首先属于配置详情页的一部分，不单独抬成配置子菜单主入口
- 强实时信息优先使用 WebSocket 推送，不依赖高频轮询

## 信息架构

### 1. 左侧主导航

沿用旧版结构：

- 首页
- 设置
- 帮助
- 配置列表
- 退出登录
- 底部系统状态入口

每个配置展开后仅保留四个子入口：

- 概览
- Mesh 网络
- 配置应用
- 端点控制

### 2. 首页

首页对应旧版 `index.html`，职责如下：

- 展示配置列表
- 创建配置
- 进入配置详情

### 3. 配置详情页

对应旧版 `config_detail.html`，页面应包含：

- 顶部配置概览卡
  - 配置名称
  - 启用状态
  - 描述
  - 虚拟网段
  - 默认监听端口
  - 默认 MTU
  - 默认 DNS
- 配置编辑入口
- 配置删除入口
- 节点列表
- 节点相关常用操作入口

### 4. Mesh 页面

对应旧版 `config_mesh.html`，页面结构如下：

- 左侧端点列表
- 右侧节点信息卡
- 右侧连接管理区
- WireGuard 配置预览

### 5. 配置应用页

对应旧版 `config_apply.html`，页面结构如下：

- 左侧节点列表
- 配置级自动同步状态
- 右侧节点状态栏
- 双栏编辑区
  - 左侧系统态预览
  - 右侧同步态配置

### 6. 端点控制页

对应旧版 `endpoint_control.html`，页面结构如下：

- 左侧节点列表
- 右侧运行状态
- 远程控制区
- 控制日志区

### 7. 设置页

设置页保留旧版结构：

- 修改登录密码
- 客户端 MQTT 配置
- 备份与恢复

### 8. 帮助页

保留旧版帮助入口和占位位置。

### 9. 系统状态页

用于承接侧栏底部的系统状态入口，展示：

- 健康检查
- 聚合系统状态

## 路由方向

- `/login`
- `/`
- `/configs`（兼容入口，重定向到 `/`）
- `/configs/:configId`
- `/configs/:configId/nodes`
- `/configs/:configId/mesh`
- `/configs/:configId/apply`
- `/configs/:configId/endpoints`
- `/settings`
- `/help`
- `/backups`（兼容入口，重定向到 `/settings`）
- `/system`

说明：

- `/configs/:configId/nodes` 仍作为节点维护页保留
- 但配置子菜单不单独展示“节点”
- 用户主要从配置详情页进入节点管理
- 节点维护页提供新增、编辑、删除、生成密钥、推荐虚拟 IP 和跨页跳转
- 备份恢复归属于设置页，不再单独作为一级页面承载

## 前端状态原则

- 页面只缓存展示状态
- 配置三态以后端返回为准
- 首屏走 REST
- 强实时状态走 WebSocket
- 不在前端复制后端业务决策逻辑
