# 安全边界

## 核心原则

后端是唯一可信边界。前端提交的所有内容都必须被视为不可信输入。

## 前后端边界

前端可以做：

- 输入格式提示。
- 必填提示。
- UI 权限隐藏。
- 交互确认。

后端必须做：

- 身份认证。
- 权限校验。
- 字段校验。
- 资源归属校验。
- 状态转换校验。
- 操作审计。
- 敏感数据过滤。

## 敏感信息

需要严格控制：

- 管理员密码。
- Session secret。
- WireGuard private key。
- MQTT password。
- 一次性绑定 token。
- Client identity key。
- 备份包。

约束：

- API 默认不返回敏感字段。
- 必须返回时使用专门接口和权限。
- 日志不得记录明文密钥和密码。
- 备份包包含 WireGuard 私钥和客户端 MQTT 密码，必须按敏感备份保存、传输和删除。
- 备份恢复需要明确审计。

## API 安全

建议：

- 统一错误响应，避免泄漏内部堆栈。
- 使用 HttpOnly Cookie 管理会话。
- 对写操作启用 CSRF 防护或 SameSite 策略。
- 对登录、一次性绑定命令、控制命令增加速率限制。
- 所有批量操作都在后端重新计算授权资源范围。

## 正式访问来源

正式模式以部署环境变量 `WFM_PUBLIC_ORIGIN` 作为主来源：

- 公网请求 Host 必须与主来源 Host 一致，反向代理必须保留可信 `Host`。
- `WFM_EXTRA_ALLOWED_ORIGINS` 只扩展请求 `Origin` 白名单，不扩展 Host 白名单。
- 带 `Origin` 的请求必须同时满足 Host 与 Origin 边界。
- CLI、curl、MCP 客户端等无 `Origin` 请求也只能通过主来源 Host 进入。
- 开发例外模式 `WFM_ENABLE_DEV_TEST_API=true` 不启用上述正式来源限制。

内部基础设施回调按单独内部认证边界处理，不依赖公网来源 Host。

## MCP 安全

MCP 使用单独 Token，不复用管理后台登录 Token。Token 明文由数据库保存，以便 AI 接入页按产品要求反复查看、复制和吊销。

- MCP Token 权限只有 `read` 与 `write`。
- `read` 只能读取系统事实、投影和诊断结果。
- `write` 只表示有资格申请写动作，所有写工具仍必须触发 MCP 标准 elicitation 交互确认。
- 客户端不支持确认交互、用户拒绝或确认载荷不满足要求时，服务端不得执行写动作。
- MCP Resource / Tool 调用必须记录 Token、目标、影响、确认结果和执行结果审计。
- MCP 不处理管理员密码，不提供快照创建、导入、恢复或删除能力。
- MCP 只允许读取快照元数据，并在用户确认后为已有快照生成 5 分钟的 `snapshot_export` 下载 URL。
- MCP 下载类工具不传输文件内容，只返回绑定单个文件的短期下载 URL；该 URL 的 token 不能访问其它文件或业务 API。

## 端点控制安全

动态节点控制属于高风险操作。

要求：

- 控制命令必须记录审计日志。
- 命令 request_id 必须可追踪。
- ACK 必须校验 config_id、node_id、request_id。
- 客户端身份需要绑定节点。
- 过期或已使用的一次性绑定 token 不可重复使用。

## 前端安全

要求：

- 不使用 `v-html` 渲染不可信内容。
- 不在浏览器持久化敏感凭据。
- 上传文件必须由后端校验类型、大小和内容。
- 所有危险操作需要用户确认。
