# 安全边界

## 核心原则

后端是唯一可信边界。前端提交的所有内容都必须被视为不可信输入。

## 前后端边界

前端可以做：

- 输入格式提示。
- 必填提示。
- UI 权限隐藏。
- 交互确认。

后端必须做：

- 身份认证。
- 权限校验。
- 字段校验。
- 资源归属校验。
- 状态转换校验。
- 操作审计。
- 敏感数据过滤。

## 敏感信息

需要严格控制：

- 管理员密码。
- Session secret。
- WireGuard private key。
- MQTT password。
- 一次性绑定 token。
- Client identity key。
- 备份包。

约束：

- API 默认不返回敏感字段。
- 必须返回时使用专门接口和权限。
- 日志不得记录明文密钥和密码。
- 备份包包含 WireGuard 私钥和客户端 MQTT 密码，必须按敏感备份保存、传输和删除。
- 备份恢复需要明确审计。

## API 安全

建议：

- 统一错误响应，避免泄漏内部堆栈。
- 使用 HttpOnly Cookie 管理会话。
- 对写操作启用 CSRF 防护或 SameSite 策略。
- 对登录、一次性绑定命令、控制命令增加速率限制。
- 所有批量操作都在后端重新计算授权资源范围。

## 端点控制安全

动态节点控制属于高风险操作。

要求：

- 控制命令必须记录审计日志。
- 命令 request_id 必须可追踪。
- ACK 必须校验 config_id、node_id、request_id。
- 客户端身份需要绑定节点。
- 过期或已使用的一次性绑定 token 不可重复使用。

## 前端安全

要求：

- 不使用 `v-html` 渲染不可信内容。
- 不在浏览器持久化敏感凭据。
- 上传文件必须由后端校验类型、大小和内容。
- 所有危险操作需要用户确认。
