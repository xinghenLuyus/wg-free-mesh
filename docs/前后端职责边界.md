# 前后端职责边界

## 目标

本项目后续会开放对外 API，并聚合 MCP 协议能力。因此所有可复用的业务用例必须沉到后端，前端只作为交互界面。

## 判断标准

前端可以做：

- 页面布局、路由跳转和组件状态。
- 表单输入、按钮禁用、弹窗开关和加载反馈。
- 轻量展示映射，例如把 `dynamic` 显示为“动态节点”。
- 调用 REST API 和订阅 SSE 实时流。
- 展示后端返回的业务摘要、草稿、校验结果和状态。

前端不可以做：

- 生成 WireGuard 配置。
- 判断 Mesh 连接最终是否有效。
- 推导配置三态。
- 批量修改标签、端点或链路的一致性逻辑。
- 推导 Peer Link 默认 AllowedIPs、Endpoint 自动行为和端口选择。
- 计算未来对外 API 或 MCP 也需要复用的业务结果。

表单必填、空白字符串、基础格式等通用约束以“后端校验为准”，前端只做同语义的即时提示，不维护另一套不同规则。

## 后端用例层

后端必须提供足够完整的用例接口，让浏览器、外部 API 调用方和 MCP 聚合器都使用同一套规则。

当前已经后端化的关键用例：

- 认证状态、初始化、登录和 token 校验。
- 不同业务令牌的签发与鉴权，包括后台会话令牌和下载专用令牌。
- 配置、节点、标签、Peer Link 的增删改查。
- 标签批量应用和删除。
- 虚拟 IP 推荐与校验。
- WireGuard 配置预览。
- 系统态到同步态的生成与保存。
- 节点运行状态和实时事件聚合。
- 端点控制运行状态投影，包括客户端版本标签和 WG 配置版本最新/待同步判定。
- heartbeat 超时、detect 主动探测、info/control ACK 与 event 命令行回显的服务端投影。
- Mesh 连接草稿。
- Mesh 节点工作区连接卡片聚合。
- WireGuard PresharedKey 生成。
- 配置概览节点卡片视图模型。
- 节点下载配置页所需的文件名、下载路径、同步态配置文本和下载专用令牌聚合。
- 配置导出文件名规则，统一使用 `配置名-节点名`，非 ASCII 字符转成 ASCII 字面转义片段，例如 `u6838u5fc3u8282u70b9`。
- 拓扑异常是否上浮到首页、左侧菜单和系统状态页的判定。
- 配置、节点、Mesh 改动后需要推送哪些 SSE 页面快照的发布计划。

## Mesh 连接草稿

`GET /api/v1/configs/{config_id}/nodes/{node_id}/peer-link-draft` 是新建 Mesh 连接的后端用例接口。

该接口负责：

- 校验当前节点和对端节点是否属于同一配置。
- 阻止节点连接自身。
- 按当前节点、对端节点和地址族生成双向连接草稿。
- 生成主向 `allowed_ips`，默认使用对端虚拟 IP。
- 生成反向 `allowed_ips`，默认使用当前节点虚拟 IP。
- 生成正反向自动 Endpoint 摘要。
- 生成缺少虚拟 IP 或公网入口时的警告。

前端只负责：

- 选择对端节点。
- 选择 IPv4 或 IPv6 地址族。
- 展示后端返回的草稿。
- 在用户确认后提交创建请求。

## API 与 MCP 扩展原则

后续新增能力时，先判断该逻辑是否会被外部 API 或 MCP 复用。

如果会复用，必须在后端实现为服务层用例，再由 API 暴露。前端不得先在页面里实现一份临时业务逻辑。

如果只是局部交互表现，例如展开面板、输入框清空、表格选择状态，可以留在前端。

配置概览页允许保留当前页面内的临时筛选和排序，因为它们属于用户查看方式。但节点卡片需要展示的在线状态、Peer 数等跨资源聚合字段必须由后端返回。

## 评估结论

本轮评估前，Mesh 新建连接中仍存在前端推导默认 AllowedIPs、Endpoint 摘要和自动地址选择的逻辑，不符合“业务逻辑全面下沉后端”的目标。

本轮已完成修正：新增后端 Mesh 连接草稿接口，前端改为读取草稿并展示；配置概览新增后端节点卡片视图模型，前端不再拼接运行快照与节点列表；Mesh 网络页面连接卡片由后端工作区接口聚合返回，PSK 由后端生成。
