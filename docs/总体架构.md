# 总体架构

## 架构方向

系统分为五个主要部分：

```mermaid
flowchart LR
  Browser["Browser"] --> Front["front: Vue 3 + Vite"]
  Front --> API["src: FastAPI"]
  Front --> WS["WebSocket Events"]
  API --> Domain["业务规则与状态机"]
  Domain --> DB["SQLite / 后续数据库"]
  Domain --> Files["WireGuard 配置文件"]
  Domain --> MQTT["MQTT / 后续执行器"]
  Docker["docker"] --> API
  Docker --> MQTT
  Client["client"] -. postponed .-> MQTT
```

## 前端职责

前端负责：

- 页面展示
- 表单输入
- 操作反馈
- REST 请求
- WebSocket 实时订阅

前端不负责：

- WireGuard 配置生成
- Mesh 最终有效性判断
- 配置是否可同步、可下发的最终判断
- 敏感字段签名和安全校验
- 关键业务状态计算

## 后端职责

后端负责：

- 认证与会话
- 配置、节点、Peer Link 建模
- WireGuard 配置生成
- 配置三态管理
- 运行态聚合
- 端点控制日志
- 备份恢复
- 系统状态聚合

## 配置三态

系统围绕配置文档生成工作流运行，配置至少有三个形态：

- 系统态：
  用户在系统中操作后，由系统根据配置、节点、链路自动生成的配置文本。
- 同步态：
  系统准备同步和下发的配置文本。系统态原则上自动同步到同步态，但用户可以手动编辑，也可以关闭自动同步。
- 下发态：
  同步态最终投递到客户端的配置结果。

增加同步态的目的，是为用户保留手动调整配置文件的空间。

## 页面信息架构原则

- 页面布局和主操作流向尽量向 `bak` 中已经验证过的结构收束
- 配置详情页是主工作台
- 节点、Mesh、同步、端点控制都应围绕当前配置组织

## 部署原则

本地开发：

- 前端和后端分别启动
- Vite 代理 `/api`

生产部署：

- 前端先构建 `dist`
- `dist` 复制进后端镜像
- FastAPI 同时提供 API 和静态页面
