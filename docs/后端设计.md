# 后端设计

## 目标

后端负责承载本项目的业务真相，前端负责表达、操作和反馈。

本项目的本质目标是帮助用户生成、调整、保存和下发 WireGuard 配置文档，因此后端设计必须围绕“配置生成”展开。

## 核心职责

- 用户认证与会话管理
- 配置管理
- 节点管理
- Peer Link / Mesh 规则管理
- WireGuard 配置生成
- 配置三态管理
- 端点运行态与控制日志
- SSE 实时事件
- MQTT 公网引导参数管理
- MQTT 节点账号与授权管理
- 备份恢复
- 系统状态聚合

## 配置三态模型

配置存在三个形态，后端必须明确区分。

### 系统态

- 指用户在系统页面中通过配置、节点、链路等操作得到的系统生成配置
- 这是系统根据当前业务数据自动计算出的结果
- 它反映的是当前业务模型推导出来的标准配置文本

### 同步态

- 指系统准备同步和下发的配置文本
- 系统态原则上应自动同步到同步态
- 用户可以手动编辑同步态
- 用户可以关闭自动同步
- 增加同步态的目的，是给用户保留手动调整配置文件的空间

### 下发态

- 指同步态最终下发到客户端的配置
- 同步态原则上应自动下发到下发态
- 客户端通过绑定、MQTT 心跳、事件、ACK 和服务管理接口接入，下发态用于表达后端已准备投递和客户端回报结果

## 后端状态原则

- 系统态来自业务数据计算
- 同步态允许人工覆盖
- 下发态代表实际投递结果
- 页面必须能明确看出三态之间是否一致
- 不能把同步态和系统态混成一个字段

## 认证模块

认证模块采用三态状态机：

- `setup_required`：数据库中没有有效 `admin` 密码哈希，系统只能访问初始化、登录状态和健康检查接口。
- `anonymous`：系统已初始化，但请求没有有效 Bearer Token。
- `authenticated`：请求携带有效后台会话 Bearer Token，业务接口放行。

数据库初始化不写入默认密码。只要 `auth_admin_password_hash` 不存在、为空或不是合法 `pbkdf2_sha256` 哈希格式，就视为需要初始化。历史默认值 `admin123` 不再作为可登录密码使用。

认证数据保存于 `system_settings`：

- `auth_admin_password_hash`：管理员密码哈希。
- `auth_token_secret`：Bearer Token HMAC 签名密钥。
- `auth_password_updated_at`：密码更新时间。

密码哈希使用 `pbkdf2_hmac(sha256)`，token 使用 HMAC-SHA256 签名结构。后台会话令牌默认有效期为 24 小时，由 `WFM_AUTH_TOKEN_EXPIRE_MINUTES` 控制；下载令牌默认有效期由 `WFM_AUTH_DOWNLOAD_TOKEN_EXPIRE_MINUTES` 控制。修改密码后重新生成 `auth_token_secret`，旧 token 全部失效。

修改密码接口必须同时满足：

- 请求携带有效后台 `session` token。
- `current_password` 能通过当前密码哈希校验。
- `new_password` 不能与当前密码一致，校验通过 `verify_password(new_password, current_password_hash)` 完成。

修改密码成功时，后端先写入新密码哈希，再轮换 `auth_token_secret`，最后使用新 secret 签发新的后台会话 token 并返回给前端。这样用户不需要重新登录，同时旧 token 会立即失效。

令牌分两类：

- `session`：管理员后台会话令牌，权限视为 `["*"]`。
- `download`：下载专用令牌，权限视为 `["config.node.download"]`，并严格绑定 `config_id` 与 `node_id`。

除 `/api/v1/auth/state`、`/api/v1/auth/setup`、`/api/v1/auth/login`、`/api/v1/auth/session`、`/api/v1/auth/logout`、`/api/v1/system/health` 外，业务接口统一通过 `require_current_user` 依赖校验 `Authorization: Bearer <token>`。下载 `.conf` 文件例外，改由下载专用依赖校验 `download_token`。

路由组织上，默认受后台会话保护的业务域统一使用 `SessionProtectedAPIRouter` 收束鉴权，不再依赖 `router.py` 在汇总层额外挂载一层全局依赖。这样各业务域的默认权限边界在路由模块内可见，下载等例外接口再通过独立 router 单独声明。

SSE 实时流通过 `Authorization: Bearer <access_token>` 鉴权访问 `/api/v1/events/stream`。

## 分层

### API 层

路径：`src/app/api/v1/`

职责：

- 绑定请求
- 返回响应
- 暴露 SSE 实时流
- 只做轻量协调

### Service 层

路径：`src/app/services/`

职责：

- 编排用例
- 维护拓扑规则与 Mesh 完整性
- 调度配置刷新、同步、端点控制
- 负责快照压缩包的创建、恢复、导入导出和索引修复
- 维护客户端绑定、MQTT 凭据签发和 EMQX 授权回查

### Projection 层

路径：`src/app/projections/`

职责：

- 生成首页配置列表、配置概览、系统状态等页面级快照
- 让前端页面复用同一份读模型

### Event 层

路径：`src/app/events/`

职责：

- 根据业务变更生成实时发布计划
- 统一发出配置列表、配置概览、系统状态和节点工作区等 SSE 快照

### Repository 层

路径：`src/app/repositories/`

职责：

- 持久化访问
- 配置预览生成
- 三态状态保存
- 快照元数据存取

### Infrastructure 层

路径：`src/app/infrastructure/`

职责：

- SQLite 连接
- 配置文件目录
- 备份目录
- 后续 MQTT / 执行器接入点

## 标签业务

标签是配置级资源，节点通过 `tags` 字段引用标签名称。

后端负责：

- 创建配置标签。
- 统计标签使用数量。
- 批量给端点应用标签。
- 删除配置标签时，从当前配置下所有端点移除该标签。
- 替换或移除单个端点的标签。
- 校验批量操作中的端点必须属于当前配置。

前端只提交标签名称和端点选择，不在浏览器中遍历节点执行批量业务。

## 端点启停与软删除

节点使用 `enabled` 表示端点是否参与当前配置。`enabled=false` 是可恢复软删除态：

- 端点数据仍保留，可以在端点设置中修改和重新启用。
- 端点仍计入配置节点总数。
- 端点不计入动态节点、静态节点、在线节点、Peer、同步和系统状态等活跃统计。
- 端点不参与 WireGuard 配置生成、同步态刷新、下载配置、客户端下发、远程控制、客户端绑定和 MQTT 授权。
- 禁用端点的 Mesh 页面只读展示所有历史相关连接。
- 禁用端点的配置预览、端点控制、下载配置能力全部关闭。
- 禁用端点不是重置客户端：已完成客户端接入的动态端点必须保留 `client_initialized`、MQTT 身份和客户端版本/主机名等绑定信息。只有显式重置客户端操作才允许清空这些字段。

禁用端点时，后端必须在同一事务中：

1. 更新 `nodes.enabled = 0`。
2. 停用所有 `local_node_id` 或 `peer_node_id` 指向该节点的 `peer_links`。
3. 将运行态重置为未知/不可参与状态，Peer 统计归零。
4. 将客户端在线态标记为离线，并清理未使用的一次性绑定 token，但不得清空已绑定客户端身份。
5. 调度配置刷新，并发布配置列表、配置概览、节点工作区和系统状态实时事件。

重新启用端点只更新 `nodes.enabled = 1`，不自动恢复历史 Mesh 对，也不重新初始化客户端。动态端点重新启用后继续使用原客户端绑定，运行状态以客户端重新上报为准。用户可以从启用端点侧手动编辑、启用、停用或删除历史 Mesh 对。

禁用端点相关 Mesh 操作规则：

- 禁用端点自身页面只允许查看 Mesh，不允许创建、编辑、启停或删除。
- 启用端点侧看到指向禁用端点的 Mesh 对时，允许编辑、启停和删除。
- 后端不在启用已有 Mesh 对时因为对端禁用而阻止保存；拓扑校验负责报告启用连接引用不存在或已禁用端点。
- 删除异常 Mesh 对不受拓扑失败阻止，用于修复错误状态。

拓扑校验需要忽略禁用端点本身，但必须把启用 Mesh 连接引用缺失或禁用端点视为错误。异常节点归属只标记仍启用且需要处理该异常连接的一侧，禁用端点本身不显示 Mesh 异常标签。虚拟 IP 唯一性和推荐仍需要把禁用端点视为已占用，避免重新启用时冲突。

## 公网地址与 Endpoint

节点公网地址分为两个公网入口字段：

- `ipv4_address`：公网 IPv4 入口，可填写 IP 或域名。
- `ipv6_address`：公网 IPv6 入口，可填写 IP 或域名。

不能把这两个字段合并为单个“公网端点”。域名不是独立地址族，两个公网入口都允许使用域名作为 WireGuard Endpoint host。

Mesh Peer Link 的自动 Endpoint 根据 `endpoint_ref_family` 选择地址来源：

- `ipv4`：引用对端 `ipv4_address`。
- `ipv6`：引用对端 `ipv6_address`。

后端负责校验：

- `auto` 模式是尽力生成：对端对应公网入口存在则写入 Endpoint，不存在则留空。
- `none` 模式强制不写 Endpoint。
- `manual` 模式必须填写 Host 和 Port。
- 公网入口被清空时，系统态重新计算，相关自动 Endpoint 会自然消失，不因为自动引用阻止保存。
- 生成 WireGuard Endpoint 时，只有 Host 是 IPv6 字面量才加方括号；域名不加方括号。
- `PersistentKeepalive` 必须依赖 Endpoint 是否实际存在：无 Endpoint 时后端直接清空 keepalive 入库；有 Endpoint 且 keepalive 为空时视为“未设置”。

## 业务逻辑下沉原则

后端是业务真相来源。凡是后续对外 API、MCP 聚合器、自动化任务或多端界面需要复用的逻辑，都必须放在后端 Service/Repository 用例中。

前端只能做展示、输入和调用，不应在浏览器里实现可复用业务规则。

当前重点边界：

- Mesh 新建连接的默认 `allowed_ips`、正反向方向、Endpoint 自动摘要和缺失项警告由后端 `peer-link-draft` 接口生成。
- Mesh 网络页面的连接卡片由后端 `mesh-workspace` 接口按 `link_group_id` 聚合返回。
- WireGuard PresharedKey 由后端生成，前端不得在浏览器中生成 PSK。
- 配置概览节点卡片需要的在线状态、Peer 数等跨资源聚合字段由后端 `overview.node_cards` 返回。
- 标签批量应用、删除标签并从端点移除、端点归属校验由后端执行。
- 虚拟 IP 推荐、重复校验和子网合法性由后端执行。
- WireGuard 配置文本、系统态、同步态和同步状态由后端生成和保存。
- 节点下载配置页所需的文件名、下载路径、同步态配置文本和下载专用令牌由后端统一提供。
- 所有导出配置文件名统一使用 `配置名-节点名` 规则；当名称中出现非 ASCII 字符时，必须转成 ASCII 字面转义片段，例如 `核心节点 -> u6838u5fc3u8282u70b9`。后续所有配置导出命名都必须复用这一规则，不能直接落中文文件名。
- 前端只能展示后端返回的草稿、校验消息和状态。
- 请求字段缺失、空白或格式错误时，后端要返回稳定错误码、英文默认消息和完整 `detail`；前端按当前语言翻译错误码与字段校验提示，不能依赖后端中文 message。

### 全局下载工具

客户端下载由后端统一提供选项、构建和文件分发能力。下载源分为：

- `github_release`：GitHub 发布源，当前仅预留，不执行真实下载。
- `local_build`：本地源码构建，服务端在 `client/` 目录下执行固定 Go 构建命令，分别构建 `cmd/ctl` 和 `cmd/agent`，打包为一个 zip。

本地构建约束：

- 项目唯一版本源是 `src/pyproject.toml` 的 `[project].version`；后端 `app_version`、客户端下载接口版本、zip 文件名和客户端二进制注入版本都读取该字段。
- 服务端运行环境必须存在 Go 工具链。
- 用户只能选择后端枚举的 `goos` 与 `goarch`，不能传入自定义命令、路径或构建参数。
- 后端构建客户端时必须通过 Go `ldflags` 注入 `wfm/client/internal/bind.Version`，不能依赖客户端源码里的开发占位版本。
- 构建产物缓存到后端运行数据目录 `data/artifacts/clients/`；同版本、同系统、同架构命中缓存时直接复用。本地开发如果从 `src/` 启动后端并使用 `uvicorn --reload`，应通过 `--reload-exclude data` 排除运行数据目录，避免产物写入触发重载。
- 构建失败时返回底层错误摘要，方便定位容器缺少 Go、依赖或交叉编译失败等问题。

配置批量下载读取同步态配置，不自动触发系统态到同步态刷新。用户选择配置和端点后，后端校验端点归属、启用状态和同步态内容，并将所选 `.conf` 文件打包为 zip。禁用端点不参与批量下载。批量配置包是临时产物，每次生成新包时后端会删除 `data/artifacts/config-bulk/` 下已有 zip，只保留最新一次生成结果。

## MQTT 集成原则

当前推荐集成方式：

- Broker 继续使用 EMQX
- `wfm` 服务端作为 MQTT 账号与 ACL 真相源
- 客户端不直接参与 EMQX 账号生成逻辑
- Docker 部署下，EMQX 继续作为独立容器运行，但配置切换和共享密钥由 `wfm` 环境变量统一控制

推荐拆分：

- **AuthN**：EMQX 内建账号库
- **AuthZ**：EMQX HTTP Authorization 回查 `wfm`

环境变量边界：

- `src/.env`
  - 只负责后端自身配置，例如调试、CORS、认证有效期、时区、开发测试开关
- `docker/.env`
  - 统一负责所有 EMQX / MQTT 相关配置
  - 在 Docker 场景下同时作为 `app` 与 `emqx` 的完整注入源

后端必须负责：

- 动态节点 bind 时生成或轮换节点专属 MQTT 用户名/密码
- 调 EMQX 管理 API 创建、更新、禁用或删除对应账号
- 通过内部授权接口判定某个节点是否允许 pub/sub 某个 topic
- 通过 `WFM_EMQX_AUTHZ_SHARED_KEY` 和 `/api/internal/emqx/authz` 承接 EMQX HTTP AuthZ 回查
- 作为高权限 MQTT 客户端订阅所有客户端上行 topic，统一消费 `heartbeat / event / config push ack / control ack / detect ack`
- 维护节点客户端初始化状态、绑定命令状态和客户端 presence 三态投影

约束：

- 一个动态节点只允许一套独立 MQTT 凭据
- topic 权限必须按 `config_id + node_id` 粒度收口
- 节点停用、删除或配置停用后，MQTT 权限必须立即失效
- 单个节点被入侵后，不允许横向访问其它节点 topic

客户端接入补充约束：

- 动态节点进入端点控制前，默认先进入客户端初始化页。
- 初始化页只展示客户端接入流程：
  - 第一步：下载客户端（前端跳转到 `/tools/download/client`）
  - 第二步：安装客户端服务；安装命令允许按系统展示为 Windows 管理员 PowerShell 的 `.\wfmctl.exe install`，以及 Linux / macOS 的 `sudo ./wfmctl install`
  - 第三步：生成并复制一次性端点绑定命令
- 除安装命令外，客户端用户命令统一收束为 `wfmctl ...`。
- 端点绑定命令默认有效期 5 分钟且只能成功使用一次。
- bind 成功后，数据库需要记录该节点 `client_initialized=true`，控制台页面才切换到真正控制页。
- 静态节点不能生成绑定命令。
- 动态节点改为静态节点时，后端必须删除其 MQTT 凭据和绑定权限，并把页面恢复为初始化态。
- 后端需要提供“重置客户端”能力，执行后删除该节点下发权限、运行态和绑定有效性，页面恢复为初始化态。
- 控制台客户端状态只保留三态：
  - `在线`
  - `掉线`
  - `离线`
- 在线状态由 `last_reachable_at` / `last_offline_at` 投影：heartbeat、detect ACK、control ACK、info ACK、config push ACK、generic ACK 或非 `offline` 的 event 任意一个在 TTL 内即可判定在线；收到 `offline` event / LWT 立即判定离线；所有可达信号超出 TTL 才判定离线。
- 客户端 heartbeat 保持 30 分钟一次，服务端在线 TTL 为 90 分钟，避免为了在线状态产生高频空闲流量。

## 界面语言偏好

后端只保存界面语言偏好，不负责网页多语言渲染：

- `system_settings.ui_locale` 保存当前控制台语言。
- `POST /api/v1/auth/setup` 接收 `locale`，初始化管理员密码时写入语言偏好。
- `GET /api/v1/settings/ui` 返回当前语言。
- `PUT /api/v1/settings/ui` 更新当前语言。

当前允许值为 `zh-CN` 和 `en-US`。后端错误消息默认使用英文作为 API/MCP 的技术回退，用户最终展示语言由前端 i18n 决定。

## 类型约束

后端代码需要通过 `mypy app`。

已清理的旧重构残留：

- `NodeRole`、`NodeStatus`、`MeshLinkStatus` 不再作为当前模型使用。
- `node_service.py`、`mesh_service.py` 对齐当前 `Node`、`NodeType` 和 `PeerLink`。
- SQLite store 的 payload 转换集中使用明确 helper，避免在业务代码中直接对 `object` 做隐式类型转换。

## 实时性策略

强实时内容优先使用 SSE：

- 节点运行快照
- 控制日志
- 配置同步状态
- 系统状态聚合
- 服务端时钟

首屏仍先走 REST，随后由 SSE 增量更新。

实时推送原则：

- 连接建立后立即发送一次系统状态快照
- 连接存活期间低频发送 `system.clock.sync`
- 端点控制页所需运行态尽量通过 `endpoint.status.updated` 直接推送完整可渲染数据，避免前端事件后再追加 HTTP reload
- 配置列表、配置概览、节点公共头、配置预览、Mesh 工作区、MQTT 设置、快照列表优先推送后端快照，不让前端自行拼状态
- Mesh、配置、节点改动后是否需要刷新首页配置列表、系统状态页和节点工作区，由统一发布计划决定，不再由各 Router 分散手写。
- 已停用配置的拓扑异常和待同步状态不再上浮到系统级摘要；这些问题仅保留在配置内部可见。
- `/api/v1/events/stream` 需要记录连接 ID、客户端地址、用户和连接时长，便于定位移动端长连接问题
- `system.clock.sync` 同时承担系统时间校时和连接活性信号，不再每秒推流
- 无在线订阅者时，服务端不做空推送

## 快照设计

- 快照压缩包保存在 `data/backups/`。
- `backups` 表只保存快照元数据索引，不再是真正的唯一数据源。
- 快照包内必须写入 `snapshot_manifest.json`，保存：
  - `id`
  - `name`
  - `created_at`
  - `note`
- 恢复快照后，后端必须重新扫描 `data/backups/` 并重建快照索引，避免“恢复后快照消失”。
- 恢复旧版本快照后，后端必须重新执行数据库初始化/兼容迁移，补齐当前版本新增表和字段，再对外发布全量实时状态。
- 恢复快照时 `snapshot_manifest.json` 只作为元数据读取，不解压到运行目录。
- 快照导入只把压缩包纳入系统管理，不直接恢复；恢复动作必须单独触发。
