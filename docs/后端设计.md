# 后端设计

## 目标

后端负责承载本项目的业务真相，前端负责表达、操作和反馈。

本项目的本质目标是帮助用户生成、调整、保存和下发 WireGuard 配置文档，因此后端设计必须围绕“配置生成”展开。

## 核心职责

- 用户认证与会话管理
- 配置管理
- 节点管理
- Peer Link / Mesh 规则管理
- WireGuard 配置生成
- 配置三态管理
- 端点运行态与控制日志
- SSE 实时事件
- MQTT 公网引导参数管理
- 备份恢复
- 系统状态聚合

## 配置三态模型

配置存在三个形态，后端必须明确区分。

### 系统态

- 指用户在系统页面中通过配置、节点、链路等操作得到的系统生成配置
- 这是系统根据当前业务数据自动计算出的结果
- 它反映的是当前业务模型推导出来的标准配置文本

### 同步态

- 指系统准备同步和下发的配置文本
- 系统态原则上应自动同步到同步态
- 用户可以手动编辑同步态
- 用户可以关闭自动同步
- 增加同步态的目的，是给用户保留手动调整配置文件的空间

### 下发态

- 指同步态最终下发到客户端的配置
- 同步态原则上应自动下发到下发态
- 客户端暂缓时，后端先保留下发所需字段和状态位

## 后端状态原则

- 系统态来自业务数据计算
- 同步态允许人工覆盖
- 下发态代表实际投递结果
- 页面必须能明确看出三态之间是否一致
- 不能把同步态和系统态混成一个字段

## 认证模块

认证模块采用三态状态机：

- `setup_required`：数据库中没有有效 `admin` 密码哈希，系统只能访问初始化、登录状态和健康检查接口。
- `anonymous`：系统已初始化，但请求没有有效 Bearer Token。
- `authenticated`：请求携带有效后台会话 Bearer Token，业务接口放行。

数据库初始化不写入默认密码。只要 `auth_admin_password_hash` 不存在、为空或不是合法 `pbkdf2_sha256` 哈希格式，就视为需要初始化。历史默认值 `admin123` 不再作为可登录密码使用。

认证数据保存于 `system_settings`：

- `auth_admin_password_hash`：管理员密码哈希。
- `auth_token_secret`：Bearer Token HMAC 签名密钥。
- `auth_password_updated_at`：密码更新时间。

密码哈希使用 `pbkdf2_hmac(sha256)`，token 使用 HMAC-SHA256 签名结构。后台会话令牌默认有效期为 24 小时，由 `WFM_AUTH_TOKEN_EXPIRE_MINUTES` 控制；下载令牌默认有效期由 `WFM_AUTH_DOWNLOAD_TOKEN_EXPIRE_MINUTES` 控制。修改密码后重新生成 `auth_token_secret`，旧 token 全部失效。

修改密码接口必须同时满足：

- 请求携带有效后台 `session` token。
- `current_password` 能通过当前密码哈希校验。
- `new_password` 不能与当前密码一致，校验通过 `verify_password(new_password, current_password_hash)` 完成。

修改密码成功时，后端先写入新密码哈希，再轮换 `auth_token_secret`，最后使用新 secret 签发新的后台会话 token 并返回给前端。这样用户不需要重新登录，同时旧 token 会立即失效。

令牌分两类：

- `session`：管理员后台会话令牌，权限视为 `["*"]`。
- `download`：下载专用令牌，权限视为 `["config.node.download"]`，并严格绑定 `config_id` 与 `node_id`。

除 `/api/v1/auth/state`、`/api/v1/auth/setup`、`/api/v1/auth/login`、`/api/v1/auth/session`、`/api/v1/auth/logout`、`/api/v1/system/health` 外，业务接口统一通过 `require_current_user` 依赖校验 `Authorization: Bearer <token>`。下载 `.conf` 文件例外，改由下载专用依赖校验 `download_token`。

路由组织上，默认受后台会话保护的业务域统一使用 `SessionProtectedAPIRouter` 收束鉴权，不再依赖 `router.py` 在汇总层额外挂载一层全局依赖。这样各业务域的默认权限边界在路由模块内可见，下载等例外接口再通过独立 router 单独声明。

SSE 实时流通过 `Authorization: Bearer <access_token>` 鉴权访问 `/api/v1/events/stream`。

## 分层

### API 层

路径：`src/app/api/v1/`

职责：

- 绑定请求
- 返回响应
- 暴露 SSE 实时流
- 只做轻量协调

### Service 层

路径：`src/app/services/`

职责：

- 编排用例
- 维护拓扑规则与 Mesh 完整性
- 调度配置刷新、同步、端点控制

### Projection 层

路径：`src/app/projections/`

职责：

- 生成首页配置列表、配置概览、系统状态等页面级快照
- 让前端页面复用同一份读模型

### Event 层

路径：`src/app/events/`

职责：

- 根据业务变更生成实时发布计划
- 统一发出配置列表、配置概览、系统状态和节点工作区等 SSE 快照

### Repository 层

路径：`src/app/repositories/`

职责：

- 持久化访问
- 配置预览生成
- 三态状态保存
- 备份文件管理

### Infrastructure 层

路径：`src/app/infrastructure/`

职责：

- SQLite 连接
- 配置文件目录
- 备份目录
- 后续 MQTT / 执行器接入点

## 标签业务

标签是配置级资源，节点通过 `tags` 字段引用标签名称。

后端负责：

- 创建配置标签。
- 统计标签使用数量。
- 批量给端点应用标签。
- 删除配置标签时，从当前配置下所有端点移除该标签。
- 替换或移除单个端点的标签。
- 校验批量操作中的端点必须属于当前配置。

前端只提交标签名称和端点选择，不在浏览器中遍历节点执行批量业务。

## 公网地址与 Endpoint

节点公网地址分为两个公网入口字段：

- `ipv4_address`：公网 IPv4 入口，可填写 IP 或域名。
- `ipv6_address`：公网 IPv6 入口，可填写 IP 或域名。

不能把这两个字段合并为单个“公网端点”。域名不是独立地址族，两个公网入口都允许使用域名作为 WireGuard Endpoint host。

Mesh Peer Link 的自动 Endpoint 根据 `endpoint_ref_family` 选择地址来源：

- `ipv4`：引用对端 `ipv4_address`。
- `ipv6`：引用对端 `ipv6_address`。

后端负责校验：

- `auto` 模式是尽力生成：对端对应公网入口存在则写入 Endpoint，不存在则留空。
- `none` 模式强制不写 Endpoint。
- `manual` 模式必须填写 Host 和 Port。
- 公网入口被清空时，系统态重新计算，相关自动 Endpoint 会自然消失，不因为自动引用阻止保存。
- 生成 WireGuard Endpoint 时，只有 Host 是 IPv6 字面量才加方括号；域名不加方括号。
- `PersistentKeepalive` 必须依赖 Endpoint 是否实际存在：无 Endpoint 时后端直接清空 keepalive 入库；有 Endpoint 且 keepalive 为空时视为“未设置”。

## 业务逻辑下沉原则

后端是业务真相来源。凡是后续对外 API、MCP 聚合器、自动化任务或多端界面需要复用的逻辑，都必须放在后端 Service/Repository 用例中。

前端只能做展示、输入和调用，不应在浏览器里实现可复用业务规则。

当前重点边界：

- Mesh 新建连接的默认 `allowed_ips`、正反向方向、Endpoint 自动摘要和缺失项警告由后端 `peer-link-draft` 接口生成。
- Mesh 网络页面的连接卡片由后端 `mesh-workspace` 接口按 `link_group_id` 聚合返回。
- WireGuard PresharedKey 由后端生成，前端不得在浏览器中生成 PSK。
- 配置概览节点卡片需要的在线状态、Peer 数等跨资源聚合字段由后端 `overview.node_cards` 返回。
- 标签批量应用、删除标签并从端点移除、端点归属校验由后端执行。
- 虚拟 IP 推荐、重复校验和子网合法性由后端执行。
- WireGuard 配置文本、系统态、同步态和同步状态由后端生成和保存。
- 节点下载配置页所需的文件名、下载路径、同步态配置文本和下载专用令牌由后端统一提供。
- 所有导出配置文件名统一使用 `配置名-节点名` 规则；当名称中出现非 ASCII 字符时，必须转成 ASCII 字面转义片段，例如 `核心节点 -> u6838u5fc3u8282u70b9`。后续所有配置导出命名都必须复用这一规则，不能直接落中文文件名。
- 前端只能展示后端返回的草稿、校验消息和状态。
- 请求字段缺失、空白或格式错误时，后端要返回稳定错误码、英文默认消息和完整 `detail`；前端按当前语言翻译错误码与字段校验提示，不能依赖后端中文 message。

## 界面语言偏好

后端只保存界面语言偏好，不负责网页多语言渲染：

- `system_settings.ui_locale` 保存当前控制台语言。
- `POST /api/v1/auth/setup` 接收 `locale`，初始化管理员密码时写入语言偏好。
- `GET /api/v1/settings/ui` 返回当前语言。
- `PUT /api/v1/settings/ui` 更新当前语言。

当前允许值为 `zh-CN` 和 `en-US`。后端错误消息默认使用英文作为 API/MCP 的技术回退，用户最终展示语言由前端 i18n 决定。

## 类型约束

后端代码需要通过 `mypy app`。

已清理的旧重构残留：

- `NodeRole`、`NodeStatus`、`MeshLinkStatus` 不再作为当前模型使用。
- `node_service.py`、`mesh_service.py` 对齐当前 `Node`、`NodeType` 和 `PeerLink`。
- SQLite store 的 payload 转换集中使用明确 helper，避免在业务代码中直接对 `object` 做隐式类型转换。

## 实时性策略

强实时内容优先使用 SSE：

- 节点运行快照
- 控制日志
- 配置同步状态
- 系统状态聚合
- 服务端时钟

首屏仍先走 REST，随后由 SSE 增量更新。

实时推送原则：

- 连接建立后立即发送一次系统状态快照
- 连接存活期间低频发送 `system.clock.sync`
- 端点控制页所需运行态尽量通过 `endpoint.status.updated` 直接推送完整可渲染数据，避免前端事件后再追加 HTTP reload
- 配置列表、配置概览、节点公共头、配置预览、Mesh 工作区、MQTT 设置、快照列表优先推送后端快照，不让前端自行拼状态
- Mesh、配置、节点改动后是否需要刷新首页配置列表、系统状态页和节点工作区，由统一发布计划决定，不再由各 Router 分散手写。
- 已停用配置的拓扑异常和待同步状态不再上浮到系统级摘要；这些问题仅保留在配置内部可见。
- `/api/v1/events/stream` 需要记录连接 ID、客户端地址、用户和连接时长，便于定位移动端长连接问题
- `system.clock.sync` 同时承担系统时间校时和连接活性信号，不再每秒推流
- 无在线订阅者时，服务端不做空推送
