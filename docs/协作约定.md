# 协作约定

## 当前阶段约定

- 旧代码已经归档到 `bak/`，新架构不直接复用旧目录。
- 未经确认，不从 `bak/` 复制代码到新目录。
- 当前已进入代码骨架落地和可运行验证阶段。

## 文档同步规则

所有变更都必须同步更新文档。

必须更新文档的情况：

- 新增目录。
- 删除目录。
- 修改 API。
- 修改数据结构。
- 修改前后端职责。
- 修改安全策略。
- 修改 Docker 部署。
- 修改客户端协议。
- 迁移旧逻辑。

## 开发边界

- `src/` 只放后端。
- `front/` 只放前端。
- `client/` 当前保持空。
- `docker/` 只放容器和环境配置。
- `docs/` 只放文档。
- `bak/` 只读参考，不参与运行。
- `bak/` 已被 `.gitignore` 屏蔽，不参与版本管理。

## 工具与权限约定

- 不允许因为本地权限问题在项目中引入与业务无关的临时目录、缓存目录或替代性产物。
- 遇到依赖安装、构建、缓存目录、端口、进程、全局 store 等权限问题时，优先直接提权执行正确命令，不通过污染项目目录来绕过。
- 如果已经产生了无关目录，必须第一时间删除，并在文档中记录原因和处理方式。
- 像 `bak/`、依赖目录、运行数据目录之外的临时目录，默认视为不应进入项目结构。

## Git 约定

- 旧历史已清空，新仓库从当前重构版本重新开始。
- `bak/` 仅作为旧代码参考，禁止纳入版本管理。
- `node_modules/`、构建产物、运行数据、缓存目录禁止纳入版本管理。
- 提交前必须确认 `git status --short --ignored` 中只有预期的 ignored 项。

## 审核流程

1. 先提交架构文档。
2. 用户审核并确认。
3. 再进行目录骨架或代码生成。
4. 每完成一个阶段，更新对应文档。
