# AWG Protocol Compatibility

Select **AmneziaWG** first, then **1.5, 2.0, or 3.1**. The version applies to the whole Mesh; versions cannot be mixed within one config. New AWG configs default to 3.1.

## Version Differences

| Version | Parameters generated by WFM |
| --- | --- |
| 1.5 | S1/S2, fixed H1–H4, Jc/Jmin/Jmax, I1–I5; optional J1–J3 and Itime. S3/S4 are omitted. |
| 2.0 | S1–S4, fixed or ranged H1–H4, Jc/Jmin/Jmax, and I1–I5. |
| 3.1 | 2.0 parameters plus HeaderProtectionKey, ContentPaddingAddition, handshake timing options, RandomTrailers, and DisableCookies. |

HeaderProtectionKey in 3.1 is a shared 32-byte Base64 key for the whole Mesh, not a WireGuard private key. Enabling it requires S1–S4 to be at least 12. WFM requires equal S1–S4 when RandomTrailers is enabled, with the switch managed at config level. New 3.1 parameters use equal random S values and distinct random fixed H values. Timing and padding values are randomized too; clearing them manually uses toolchain defaults.

## Unified Generation and Manual Editing

Endpoint advanced settings → AmneziaWG local parameters provides a Random button using the saved config direction and intensity. It generates only the current endpoint draft, without changing shared S/H, keys, mechanism switches, or other endpoints. Save manually to apply. Question-mark tips explain the purpose, units, range syntax, and cautions for 3.1 local extension fields.

Config settings → Advanced settings provides whole-config random generation. Choose generic random, DNS, STUN/WebRTC, RTP/voice UDP, or QUIC Initial (experimental), then low overhead, balanced, or more disturbance. Generate shared parameters and independent parameters for all existing endpoints together. Generation changes the draft only; saving applies it and triggers config synchronization. Cancel leaves the config unchanged. Changing version discards unsaved endpoint drafts.

Every applicable field is individually editable or clearable, including in endpoint advanced settings. Directions do not constrain manual contents. Direction and intensity are saved with the config and reused for new endpoints. Preview, download, and refresh use stored concrete values and never rerandomize them. Ordinary generation preserves configured HeaderProtectionKey, DisableCookies, and shared RandomTrailers. Key rotation is a separate operation. If endpoint switches differ, explicitly select shared RandomTrailers before generating.

Directions generate CPS handshake preludes, not full protocol traffic, and do not guarantee detection avoidance. DNS uses query structure; STUN uses Binding requests with SOFTWARE attributes; RTP correlates sequence numbers, timestamps, and SSRC within the generated chain. QUIC generates one encrypted, header-protected 1200-byte Initial following [RFC 9001](https://www.rfc-editor.org/rfc/rfc9001.html), without establishing a full QUIC session. This packet changes only when regenerated; inserting random tags into its ciphertext invalidates it. These directions have not undergone actual toolchain interoperability or traffic-detection verification.

Suggested generation ranges are not manual limits. Larger packets increase MTU and bandwidth risks; shorter handshake timers can reduce stability on poor networks. Nonzero ContentPaddingAddition takes precedence over random transport trailers; the two are not simply additive.

## Toolchain Requirements

WFM generates configs and invokes the toolchain; it does not install or upgrade AmneziaWG itself. Clients use `awg` and `awg-quick` on Linux/macOS, or `amneziawg.exe` on Windows. **The WFM client version is not the AWG protocol version.**

Before switching, verify that each endpoint's installed AmneziaWG implementation supports the target version and selected parameters. Parameter support can differ across implementations and versions; command availability alone does not establish compatibility. Incompatible toolchains report execution errors; WFM does not silently downgrade.

Consult the [official AmneziaWG documentation](https://docs.amnezia.org/documentation/amnezia-wg/) and [amneziawg-go](https://github.com/amnezia-vpn/amneziawg-go) for your operating system and implementation.

## Version Switching

The backend converts incompatible S/H parameters when switching versions. The form displays the converted values; saving applies the change. Switching to 1.5 collapses H ranges to fixed values and disables S3/S4. Switching to 3.1 generates compatible S/H values and a missing HeaderProtectionKey. Extension options unused by the selected version remain stored but are not emitted; WFM does not keep historical per-version config copies.

AWG version switches use the AWG toolchain. Config synchronization stops running tunnels on dynamic endpoints, writes the config, and restarts tunnels that were running beforehand. Static endpoints require downloading and applying the new config manually. Coordinate the switch across the Mesh: temporary disconnection is possible, and endpoint toolchains are not upgraded automatically.

See [Protocol Parameters](/en/reference/protocols) for complete rules.
